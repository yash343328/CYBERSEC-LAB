🗄️ SQL Injection Attack Lab

SQL Injection tab hota hai jab attacker malicious SQL code ko input field mein dalta hai, aur application us code ko database query mein execute kar deta hai. Yeh OWASP Top 10 ka #1 vulnerability raha hai saalon tak. Is lab mein aap ek simulated vulnerable login form pe SQLi attacks karoge — aur phir dekhoge kaise secure kiya jaata hai.

Kaise kaam karta hai:
Normal query: SELECT * FROM users WHERE username='admin' AND password='secret'
SQLi payload: username = admin' OR '1'='1
Resulting query: SELECT * FROM users WHERE username='admin' OR '1'='1' -- ' AND password='anything'
Result: '1'='1' hamesha true hota hai → login bypass!

// 🛡️ PREVENTION TECHNIQUES

1. Parameterized Queries (Best!)
db.query("SELECT * FROM users WHERE user=? AND pass=?", [user, pass])
2. ORM Use Karo
User.findOne({ where: { username, password } }) // SQLAlchemy, Sequelize, etc.
3. Input Validation + Whitelisting
Only allow alphanumeric in usernames. Reject special chars.
4. Least Privilege Database User
App DB user ko sirf SELECT/INSERT access do. DROP/UPDATE restrict karo.
5. WAF (Web Application Firewall)
ModSecurity, Cloudflare WAF — SQLi patterns detect karke block karta hai

// KEY CONCEPTS LEARNED

  • SQL Injection kaise kaam karta hai
  • Authentication bypass aur data extraction
  • String concatenation kyun dangerous hai
  • Parameterized queries — single best defense
  • UNION attacks se table data leak hona
  • Blind SQLi — error-based aur time-based
  • Database privilege escalation
